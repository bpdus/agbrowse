# 계획 의뢰: 에이전트용 로컬 브라우저 게이트웨이 (agbrowse 포크 기반)

## 배경과 의도 (정재)
- Grok Bot(클라우드, 박스 grokbot-box는 정재 tailnet 안에 있음)과 iMac/MacBook의 codex·claude·grok CLI가 정재 PC의 실제 로그인 상태 브라우저를 도구로 쓰게 하고 싶다.
- 화면 좌표 클릭(컴퓨터 유즈)이 아니라, 에이전트가 호출하는 브라우저 도구가 목표.
- 서버 역할 기기는 항상 켜진 iMac(Tailscale: jjbyuns-imac, 100.79.8.49). herdr web ui가 이미 tailscale serve로 tailnet에만 열려 있다.
- Aside 브라우저 정적 분석 결과는 같은 폴더 aside-report.md 참고(로컬 데몬 127.0.0.1, CDP는 로컬, 설치별 키로 challenge 서명 → 24h 토큰, 접근성 트리+diff+ref, 승인은 코드 강제지만 기본 꺼짐). 코드 복사 금지, 설계 참고만.

## 정재의 요구 (명시)
1. 토큰을 매일 사람이 입력하지 않는다. 처음 한 번 기기 페어링 후, 서로 통신(서명/challenge)으로 짧은 토큰을 자동 갱신. 만료·폐기 가능.
2. Chromium을 새로 만들지 말고 agbrowse(https://github.com/lidge-jun/agbrowse, Chrome/CDP CLI, ref 기반 관찰·조작, 0.1.18, upstream 정지 상태로 보임)를 정재가 포크해 고도화한다. bpdus-kit에는 vendor/agbrowse 미러가 있다(현재 박스에는 agbrowse·Node22 설치 금지 정책; 게이트웨이는 iMac에서 돈다).
3. 에이전트↔브라우저 통신 표준(프로토콜)을 정의해 다른 클라이언트도 쓰게 한다. MCP를 기본 표면으로 하되, 표준 문서(메시지 스키마, 인증, 스냅샷 형식, 승인 이벤트, 오류 코드, 버전)를 별도로 둔다.
4. 네이버·쿠팡 등 일반 크롤링이 막힌 사이트에서 정재 로그인 세션으로 목록 조회·정보 수집, 장바구니 담기, 구매까지. 구매·결제·전송·게시는 정재의 명시적 승인(Grok Bot 채팅에서 구두 허가 → 서명된 일회성 승인 토큰, 금액·대상·세션에 묶임) 없이는 코드에서 실행 불가.

## 원칙·제약
- CDP/디버깅 포트는 iMac 밖으로 절대 노출하지 않는다. 게이트웨이만 tailnet(tailscale serve)에 연다. 공개 인터넷(Funnel) 금지.
- 자동화 탐지·캡차·봇 차단 우회 기능은 넣지 않는다. 사람 속도, 사이트 약관 존중, 도메인 허용 목록.
- 에이전트 전용 Chrome 프로필(평소 프로필과 분리). 비밀번호는 에이전트에게 노출하지 않는다.
- 비밀/토큰은 로그·argv에 남기지 않는다. 감사 로그(누가 무엇을)는 남긴다.
- 코딩 규칙: 계획·리뷰 Codex, 구현 Grok Build CLI, 원본 GitHub 저장소에 PR. 포크 저장소 이름·위치는 '확인 필요'.
- Grok Bot은 원격 MCP 커넥터(HTTPS URL)로 붙는 경로와, 박스에서 tailnet 주소로 직접 호출하는 경로 둘 다 검토.

## 요청
- 전체 아키텍처(구성 요소, 데이터 흐름, 신뢰 경계) 다이어그램(mermaid)과 설명.
- 페어링·토큰 자동 갱신 설계(키 종류, 저장 위치: macOS 키체인 등, 갱신 주기, 폐기, 박스 재설치 시 복구).
- 통신 표준 초안의 목차와 핵심 메시지 예시(JSON).
- agbrowse 포크에서 바꿀 점(데몬화 여부, MCP 표면, 스냅샷 형식, 승인 훅)과 upstream 라이선스 확인 항목.
- 승인 흐름(구두 허가 → 승인 토큰) 상세와 위험 시나리오(프롬프트 인젝션으로 결제 유도 등) 대응.
- 단계별 마일스톤(MVP: iMac에서 조회만 → 장바구니 → 승인 결제), 각 단계 PR 범위·테스트·되돌리기.
- 모르는 것은 '확인 필요'. 정재가 결정할 항목 목록.
