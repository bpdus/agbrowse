# 에이전트 브라우저 인수인계 (2026-10-12)

iMac 에이전트 브라우저(bpdus/agbrowse 포크) 작업의 현재 상태와 다음 할 일을 정리한 문서입니다. 기준 main은 `5cb495d`(#24)입니다. 비밀 값(토큰, 키, 비밀번호)은 이 문서에 없습니다.

## 1. 목표
- 일반 브라우저처럼 로그인이 유지될 것. 정재 님이 가장 중요하다고 한 부분입니다.
- 정재 님이 아니라 에이전트가 원격으로 실행, 조작, 재시작할 수 있을 것.
- 비밀번호는 iMac 키체인에만 저장. 워커만 읽어서 입력란에 넣고, 채팅으로는 절대 주고받지 않음.
- 결제, 게시, 전송은 에이전트가 직접 확인할 수 있는 승인을 거쳐서만 실행(decisions.md 4번).
- 2단계 인증은 정재 님이 폰에서 승인. 캡차가 나오면 에이전트는 멈추고 물어봄.

## 2. 구조
- **게이트웨이**: `node skills/browser/agent-gateway.mjs`, `127.0.0.1:7420`.
- **Tailscale Serve**(tailnet 전용, 2026-10-12 확인):
  - `https://jjbyuns-imac.tail8f1886.ts.net/` → `127.0.0.1:7317`(herdr)
  - `https://jjbyuns-imac.tail8f1886.ts.net:8443/` → `127.0.0.1:7420`(게이트웨이)
- **워커**: `skills/browser/agent-worker.mjs`. 전용 Chrome 프로필로 브라우저를 띄우고 조작합니다.
- **전용 Chrome 프로필**: `~/.agbrowse-bpdus/agent-profile`
- **소스**: `~/.agbrowse-bpdus/src`(iMac, 이 저장소 클론)
- **LaunchAgents**: `me.bpdus.agbrowse.worker`, `me.bpdus.agbrowse.gateway`. GUI 세션에서 실제 키체인으로 실행되고, 원격 재시작은 `launchctl kickstart`로 합니다. 로그는 herdr `agbrowse` 탭에서 tail로 봅니다.
- **자격증명 등록 페이지**: 게이트웨이의 `/admin/naver-credentials`(tailnet 전용). 일회용 토큰은 herdr `naver-credentials` 탭에 표시됩니다. 저장하면 iMac 키체인으로 들어갑니다.
- **iMac 접속**: `ssh imac`(jjbyun@100.79.8.49, SSH 키).

- **topbar-capture**(`cc7d0dd`): 상단바 캡처. Codex 재검토 BLOCK(sanitizer가 임의 식별자·경로를 허용, stale-lock rename 경쟁 조건). PR 없음, 미머지. stale-lock 처리 일부는 #11로 따로 반영됐습니다.
- 그 밖에 `blocklog-path`(`0ca5b60`, 경로에 토큰이 기록될 수 있어 Codex BLOCK)는 로컬에만 있었고 원격에는 없습니다(확인 필요).

## 5. 문제와 해결
1. **SSH로 띄운 Chrome에서 로그인이 사라짐**: SSH 세션에서 실행하면 "Encryption is not available"이 나오고, Playwright 기본값 `--use-mock-keychain`, `--password-store=basic` 때문에 쿠키가 유지되지 않았습니다. → #14·#15·#17로 GUI 세션 LaunchAgent + 실제 키체인으로 옮겨 해결.
2. **비밀번호 자동 로그인이 캡차에 막힘**: #18~#24로 키체인 자격증명 입력과 제출까지는 성공했지만, 제출 후 `needs_human`(영수증 질문 캡차)에서 멈췄습니다. 자동화된 Chrome에서 빠르게 입력하는 비밀번호 로그인을 네이버가 봇으로 의심하는 것으로 보입니다(추정).
3. **패스키 로그인은 성공**: 13:54 정재 님이 수동 로그인 창에서 패스키로 바로 로그인했습니다. 기기 기반 WebAuthn 승인이라 추가 검사를 건너뛰는 것으로 보입니다(추정).
4. **재시작 검증 실패**: 13:57 워커 재시작 전 첫 확인부터 `logged_out`. '로그인 상태 유지'가 꺼져 있어서 `NID_AUT`, `NID_SES`가 세션 쿠키로만 남았고 Chrome 종료 때 사라졌습니다. 장기 기기 쿠키는 디스크에 저장돼 있어 키체인 저장 자체는 정상입니다.
- 부수 이슈: 비정상 종료한 클라이언트가 `client-keys/.writer.lock`을 남기면 STATE_UNSAFE, Chrome `profile.lock`이 죽은 PID로 남으면 login-naver.sh가 거부합니다(수동으로 `.stale-<pid>`로 옮겨 처리). 이전 AUTH_INVALID는 점검 스크립트의 MCP protocolVersion 불일치(2025-06-18 vs 2025-11-25) 때문이었습니다.

## 6. 현재 막힌 지점
- 2026-10-12 13:59부터 iMac에 수동 로그인용 Chrome이 네이버 로그인 페이지로 열려 있고, 워커 LaunchAgent는 일부러 내려 둔 상태입니다. 게이트웨이는 실행 중입니다(2026-10-12 확인: `launchctl list`에 gateway만 있음).
- **정재 님 할 일**: '로그인 상태 유지'를 체크하고 로그인(패스키 가능) → Chrome을 ⌘Q로 종료 → 에이전트에게 알림.
- 그 뒤 에이전트가 워커를 다시 올리고 `launchctl kickstart`로 재시작해 `login_status`가 계속 `logged_in`인지 확인합니다.

## 8. 규칙
- **네이버 로그아웃 주소는 절대 열지 않습니다.**
- 비밀번호는 채팅에 쓰지 않습니다. iMac 키체인에만 두고 워커만 읽습니다.
- CLI 작업은 bpdus-kit cli-relay로 herdr 탭 안에서 보이게 실행합니다(box, iMac 모두).
- 구현은 기본 Luna(gpt-6-luna). 정재 님이 "grok으로 하자"고 하면 한도 소진까지 Grok 우선, 소진되면 보고하고 Luna로 복귀.
- 난이도 라우팅: easy는 계획 없이 Luna, medium은 Sol 계획, hard는 Opus 5.5 high 계획. 리뷰는 항상 Codex.
- 변경은 PR로만 합니다. Codex BLOCK이면 멈추고 승인을 받고 고칩니다.
- 단계마다 한 줄로 보고합니다(다른 봇에게는 priority true로 보고 요청).
- 확인하지 못한 내용은 '확인 필요'로 표시합니다.
