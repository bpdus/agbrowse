# 내부 화면용 IPC 구현과 검토

CLIrelay가 Node 소켓 서버와 C++ 전송 계층을 작성했습니다.
상대 CLI의 샌드박스는 Unix 소켓 bind를 거부했습니다.
상대가 검사를 통과했다고 주장하지 않았습니다.
루트가 실제 파일을 읽고 실제 소켓에서 검사했습니다.

첫 검사에서 queue 테스트의 상태 조건 오류를 발견했습니다.
Node의 자동 소켓 정리가 대체 파일도 지우는 동작을 실제로 확인했습니다.
종료 전에 소유 디렉터리를 옮겨서 대체 파일을 보존하도록 수정했습니다.
소켓과 디렉터리 신원이 바뀌면 정리를 거부합니다.

독립 CLIrelay 검토는 세 항목을 REVISE로 판정했습니다.
큰 목록, listen 직후 실패 정리와 남는 connection.json을 지적했습니다.
루트와 작성 CLI가 각 항목을 수정했습니다.
목록은 SQL의 rowid cursor와 제목 요약으로 페이지를 나눕니다.
정상 종료는 자신이 쓴 연결 파일만 제거합니다.
외부에서 바꾼 연결 파일은 보존합니다.
수정본의 후속 읽기 검토는 PASS로 끝났습니다.
검토자는 테스트를 실행하지 않았습니다.

루트가 확인한 증거는 다음과 같습니다.

- Node 전체 검사 75개가 통과했습니다. 실제 소켓과 데몬 종료 검사를 포함합니다.
- arm64 C++ 클라이언트가 Xcode clang에서 경고 없이 컴파일됐습니다.
- 현재 Mac에서 실제 C++ 소켓 검사와 Node 연결 검사 17개가 통과했습니다.
- x64 클라이언트를 현재 Mac에서 교차 컴파일했습니다.
- 실제 iMac에서 C++ 소켓 검사 16개가 통과했습니다.
- 실제 Codex가 IPC 요청을 받아 IPC_READY_20261014를 반환했습니다.

현재 Mac의 마지막 포인터 정리 보완 후, 데몬 종료 검사도 다시 통과했습니다.
시작 중 중단 시에는 연결 파일을 뒤늦게 쓰지 않도록 보완했습니다.
후속 CLIrelay PASS 이후의 작은 보완은 루트가 검사했습니다.

다른 UID의 peer 부정 검사와 반복 호출 FD 누수 검사는 미실행입니다.
이 결과는 Chromium·Mojo·스토어·브라우저 MCP 완료를 의미하지 않습니다.
원본 Chromium은 아직 컴파일 중이며, overlay는 아직 적용하지 않았습니다.
